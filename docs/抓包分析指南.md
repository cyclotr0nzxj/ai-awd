# AIAWD/1.0 协议抓包分析指南

> 使用 tcpdump + Wireshark 抓取并分析 AI-AWD Arena 完整交互过程的实操指南。

---

## 1. 抓包工具

| 工具 | 用途 | 安装 |
|------|------|------|
| **tcpdump** | 命令行抓包，生成 `.pcap` 文件 | macOS/Linux 预装 |
| **Wireshark** | GUI 分析 `.pcap`，可视化帧结构 | [wireshark.org](https://www.wireshark.org/download.html) |

本文档全程使用这两个工具。

---

## 2. 抓包命令

### 2.1 本地单机测试（服务端和客户端在同一台机器）

```bash
# === 终端 1：启动服务端 ===
PYTHONPATH=server python3 -m aiawd_server.main --host 127.0.0.1 --port 9000

# === 终端 2：开始抓包 ===
mkdir -p captures
sudo tcpdump -i lo0 -w captures/aiawd_match.pcap -s 0 'tcp port 9000'
#   -i lo0     macOS loopback 接口（Linux 用 lo）
#   -w        写入 pcap 文件
#   -s 0      抓取完整包（不截断）
#   'tcp port 9000'  只抓 AIAWD 协议流量

# === 终端 3：运行演示 ===
PYTHONPATH=server python3 examples/three_clients_demo.py

# === 回到终端 2：Ctrl+C 停止抓包 ===
```

### 2.2 局域网多机测试（服务端和客户端在不同机器）

```bash
# 服务端机器上（假设 IP 192.168.1.100）：
sudo tcpdump -i en0 -w captures/aiawd_lan_match.pcap -s 0 'tcp port 9000'
#   -i en0     实际网卡（macOS；Linux 用 eth0 或 ip a 查看）
```

### 2.3 自动化抓包脚本

仓库提供了 `captures/capture.sh` 一键脚本：

```bash
bash captures/capture.sh
# 自动检测 loopback 网卡 → 后台启动 tcpdump → 等待按回车停止
```

### 2.4 快速验证抓包结果

```bash
# 查看前 20 个包的十六进制内容
tcpdump -r captures/aiawd_match.pcap -X -c 20 | head -120

# 统计捕获了多少包
tcpdump -r captures/aiawd_match.pcap | wc -l

# 只看 JSON payload（过滤掉 TCP 包头）
tcpdump -r captures/aiawd_match.pcap -A | grep '"type"' | head -20
```

## 3. Wireshark 分析流程

### 3.1 打开 pcap 文件

```
Wireshark → File → Open → 选择 captures/aiawd_match.pcap
```

### 3.2 设置过滤器

在顶部 Filter 栏输入：

```
tcp.port == 9000
```

### 3.3 Follow TCP Stream — 最佳分析入口

右键任意 `9000` 端口的 TCP 包 → **Follow → TCP Stream**：

- 窗口显示服务端和客户端之间的**全部文本对话**
- 红色 = 客户端发往服务端，蓝色 = 服务端发往客户端
- 可以看到完整的 HELLO → WELCOME → CREATE_ROOM → JOIN → START → PHASE_SYNC → SUBMIT → RANKING 交互链
- 所有 JSON 消息都是**明文可读**的 UTF-8 文本

### 3.4 观察单条帧结构

在 Follow TCP Stream 中，切换到 **Show data as: Hex Dump**，可以清楚看到帧边界：

```
0000   00 00 00 2F 7B 22 76 22  3A 31 2C 22 73 65 71 22   .../{ "v" :1, "s eq"
0010   3A 31 2C 22 74 79 70 65  22 3A 22 48 45 4C 4C 4F   :1, "t ype ":H ELL O
0020   22 2C 22 70 61 79 6C 6F  61 64 22 3A 7B 22 64 69   ", "p ayl oad ": {"d i
...
```

- **前 4 字节** (`00 00 00 2F`) = 帧长度 = 47 字节（大端序 uint32）
- **第 5 字节起** = UTF-8 JSON 消息体，以 `{` 开头

### 3.5 截图关键证据

建议在 Wireshark 中截取以下画面：

| 编号 | 截图内容 | 截图方法 | 说明 |
|------|---------|---------|------|
| ① | TCP Stream 全览 | Follow TCP Stream 后截屏 | 展示完整的交互序列 |
| ② | 单条 HELLO 帧 | 选中 HELLO 包 + 下半区展开 TCP payload | 展示 4B 长度 + JSON body |
| ③ | 单条 MATCH_CONFIG 帧 | 同上 | 展示 Flag 下发（注意：实验报告要脱敏） |
| ④ | 广播扇出模式 | 选中 RANKING_UPDATE 包，对比 3 个客户端 TCP stream | 同一消息发往多个客户端 |
| ⑤ | ERROR 帧 | 选中 ERROR 包 | 展示异常处理消息格式 |

## 4. 帧格式分析模板

以下以一条真实的 `HELLO` 消息为例，逐字节分析 AIAWD/1.0 帧格式。

### 4.1 HEX 原始数据

```
00 00 00 5E                                          ← 4 字节长度头：0x0000005E = 94 字节
7B 22 76 22 3A 31 2C 22 73 65 71 22 3A 31 2C        ← {"v":1,"seq":1,
22 74 79 70 65 22 3A 22 48 45 4C 4C 4F 22 2C          "type":"HELLO",
22 63 6C 69 65 6E 74 5F 69 64 22 3A 6E 75 6C 6C      "client_id":null,
2C 22 72 6F 6F 6D 5F 69 64 22 3A 6E 75 6C 6C 2C      "room_id":null,
22 72 6F 6C 65 22 3A 6E 75 6C 6C 2C 22 74 73 22      "role":null,"ts"
3A 31 32 33 34 35 36 37 38 39 30 2C 22 70 61 79      :1234567890,"pay
6C 6F 61 64 22 3A 7B 22 64 69 73 70 6C 61 79 5F      load":{"display_
6E 61 6D 65 22 3A 22 41 6C 69 63 65 22 7D 7D         name":"Alice"}}
```

### 4.2 分层解析

```
┌──────────────────────────────────────────────────────────────────────┐
│  TCP 层                                                              │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  AIAWD/1.0 帧                                                   │  │
│  │  ┌────────────────────┬─────────────────────────────────────┐  │  │
│  │  │  4 字节帧头 (大端)    │  JSON Body (UTF-8)                 │  │  │
│  │  │  0x0000005E = 94     │  {"v":1,"type":"HELLO",...}       │  │  │
│  │  └────────────────────┴─────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.3 JSON Body 解析

```json
{
  "v": 1,
  "seq": 1,
  "type": "HELLO",
  "client_id": null,
  "room_id": null,
  "role": null,
  "ts": 1234567890.0,
  "payload": {
    "display_name": "Alice"
  }
}
```

### 4.4 字段逐项说明

| JSON 字段 | 含义 | 当前值 |
|-----------|------|--------|
| `v` | 协议版本号 | 1（固定） |
| `seq` | 客户端消息序列号，递增 | 1 |
| `type` | 消息类型标识符 | `"HELLO"` |
| `client_id` | 客户端 ID，HELLO 前为 null | null |
| `room_id` | 房间 ID，此时尚未加入 | null |
| `role` | 角色，此时尚未分配 | null |
| `ts` | Unix 时间戳 | 1234567890.0 |
| `payload.display_name` | 客户端显示名 | `"Alice"` |

## 5. 完整交互时序标注

以下是 `three_clients_demo.py` 运行后抓包得到的完整帧序列，在 Wireshark 的 Follow TCP Stream 中可以逐一对照：

### 5.1 Alice 的连接与房间创建

```
C→S  00 00 00 XX | {"v":1,"seq":1,"type":"HELLO",              "payload":{"display_name":"Alice",...}}
S→C  00 00 00 XX | {"v":1,"type":"WELCOME",                     "payload":{"client_id":"client_0001",...}}
C→S  00 00 00 XX | {"v":1,"seq":2,"type":"CREATE_ROOM_REQ",     "payload":{"room_name":"AI AWD Demo",...}}
S→C  00 00 00 XX | {"v":1,"type":"CREATE_ROOM_RES",             "payload":{"ok":true,"room":{...}}}
```

### 5.2 Bob 加入房间

```
C→S  00 00 00 XX | {"v":1,"type":"HELLO",                       "payload":{"display_name":"Bob",...}}
S→C  00 00 00 XX | {"v":1,"type":"WELCOME",                     "payload":{"client_id":"client_0002",...}}
C→S  00 00 00 XX | {"v":1,"seq":2,"type":"JOIN_ROOM_REQ",       "payload":{"role":"player",...},"room_id":"room_001","role":"player"}
S→C  00 00 00 XX | {"v":1,"type":"JOIN_ROOM_RES",               "payload":{"ok":true,...}}
S→A  00 00 00 XX | {"v":1,"type":"ROOM_UPDATE",                 "payload":{"room":{...}}}              ← 广播给 Alice
S→B  00 00 00 XX | {"v":1,"type":"ROOM_UPDATE",                 "payload":{"room":{...}}}              ← 广播给 Bob
```

### 5.3 比赛开始 → 阶段推进

```
C→S  00 00 00 XX | {"v":1,"type":"START_MATCH_REQ",             "room_id":"room_001","role":"player"}
S→A  00 00 00 XX | {"v":1,"type":"MATCH_CONFIG",                "payload":{"match_id":"match_001","flag":"FLAG{...}",...}} ← 单播给 Alice
S→B  00 00 00 XX | {"v":1,"type":"MATCH_CONFIG",                "payload":{"match_id":"match_001","flag":"FLAG{...}",...}} ← 单播给 Bob
S→ALL 00 00 00 XX | {"v":1,"type":"PHASE_SYNC",                 "payload":{"match":{"phase":"PREPARE"},...}} ← 广播
S→ALL 00 00 00 XX | {"v":1,"type":"PHASE_SYNC",                 "payload":{"match":{"phase":"DEFENSE"},...}}
S→ALL 00 00 00 XX | {"v":1,"type":"PHASE_SYNC",                 "payload":{"match":{"phase":"ATTACK"},...}}
```

**关键观察**：`MATCH_CONFIG` 是**单播**（只发给对应客户端），而 `PHASE_SYNC` 是**广播**（所有客户端同时收到相同内容）。

### 5.4 Flag 提交 → 排名更新

```
C→S  00 00 00 XX | {"v":1,"type":"SUBMIT_FLAG_REQ",            "payload":{"match_id":"match_001","flag":"FLAG{...}",...}}
S→C  00 00 00 XX | {"v":1,"type":"SUBMIT_FLAG_RES",            "payload":{"ok":true,"submission":{...}}}
S→ALL 00 00 00 XX | {"v":1,"type":"EVENT",                     "payload":{"event_type":"FLAG_CAPTURED",...}}
S→ALL 00 00 00 XX | {"v":1,"type":"RANKING_UPDATE",            "payload":{"rankings":[{...},{...}]}}
```

**关键观察**：`SUBMIT_FLAG_RES` 只发给提交者，但 `EVENT` 和 `RANKING_UPDATE` 广播给所有成员（参赛玩家 + 观战）。

### 5.5 广播扇出模式可视化

```
服务端收到一条 SUBMIT_FLAG_REQ 后：

                   ┌─────────────────────┐
                   │     TCPGateway      │
                   │   _broadcast()      │
                   └───┬──────┬──────┬───┘
                       │      │      │
              ┌────────▼┐ ┌───▼───┐ ┌▼────────┐
              │ Alice   │ │ Bob   │ │ Carol   │
              │ Player  │ │Player │ │Spectator│
              └─────────┘ └───────┘ └─────────┘
              
          每条相同消息被写入 3 个 TCP stream
```

在 Wireshark 中可以观察到：同一个 JSON payload 出现在 3 个不同的 TCP 连接中，时间戳相差在毫秒级。

## 6. 错误处理帧示例

### 6.1 非 JSON 数据 → BAD_REQUEST

```
C→S  00 00 00 0A | not-a-json
S→C  00 00 00 XX | {"v":1,"type":"ERROR","payload":{"code":"BAD_REQUEST","message":"Invalid JSON body"}}
```

### 6.2 HELLO 之前发送其他消息

```
C→S  00 00 00 XX | {"v":1,"type":"PING","seq":1,"payload":{}}
S→C  00 00 00 XX | {"v":1,"type":"ERROR","payload":{"code":"BAD_REQUEST","message":"HELLO is required before other messages"}}
```

### 6.3 非 ATTACK 阶段提交 Flag

```
C→S  00 00 00 XX | {"v":1,"type":"SUBMIT_FLAG_REQ","room_id":"room_001","payload":{"flag":"FLAG{test}"...}}
S→C  00 00 00 XX | {"v":1,"type":"SUBMIT_FLAG_RES","payload":{"ok":false,"submission":{"code":"INVALID_PHASE"}}}
```

### 6.4 客户端断开

Wireshark 中会看到 TCP [FIN, ACK] 包，服务端随后向房间内其他成员广播 `ROOM_UPDATE`（status: DISCONNECTED）。

## 8. 常见问题

| 问题 | 解决方案 |
|------|---------|
| `tcpdump: lo0: No such device exists` | Linux 用 `-i lo`，macOS 用 `-i lo0`，用 `ifconfig` 确认网卡名 |
| Wireshark 看不到明文 JSON | 检查 Filter 是否正确，确保端口是 9000 |
| pcap 文件为空 | 确认 tcpdump 在服务端启动前已运行；检查端口过滤条件 |
| 捕获了太多无关流量 | 在 Filter 后添加 `and tcp port 9000` |
